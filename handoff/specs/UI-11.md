# UI-11 — Scale-bar measurement modes (user request 2026-09-24)

## Problem
The manual calibration uses two clicks. It is hard to keep the clicks exactly level, so the line comes out slightly tilted and the measured length is slightly wrong.

## Solution: a mode toggle in the calibration dialog (segmented control, remembered in settings)
1. **Rectangle** (the user asked for this)
   - Drag a box over the scale bar. Only the box **width** (horizontal) counts as the bar length in pixels. Height is ignored, so a tilted drag can't happen.
   - Once drawn, the box can be edited: 8 resize handles, move by dragging inside, arrow keys nudge 1 px (Shift+arrow nudges 10 px). The bar length in px updates live.
   - **Snap to bar** (on by default): after drawing or resizing, detect the bar's left and right ends inside the box (reuse/extend `core.scale_bar.find_scale_bar_line` with an ROI) and snap the vertical edges to them. A small "Snapped ✓" indicator is shown. Undo the snap, or hold Alt while dragging, to turn it off.
2. **Level line** (the recommended better option; make it the default)
   - Same two clicks, but the line is **locked horizontal**: the second point takes the first point's y. Both end handles stay draggable afterwards, but only left/right.
   - Show a **magnifier loupe** (about 4× zoom with crosshair) next to the cursor while placing or dragging an end, so the bar's edge can be hit to the pixel.
   - Ends also snap to the detected bar edge when within ~6 px (same detector; Alt turns snapping off).
3. **Free line** (the existing two-click method): kept for tilted images, with an angle readout (e.g. "tilt 1.8°") and a warning when the tilt is above 1°. When the tilt is small, offer a "Level it" button.

- The auto-prefill that already exists (from `find_scale_bar_line`) should appear as an editable rectangle or level line, depending on the mode.
- The known length field (µm/nm) and the resulting µm/px readout stay as they are. The readout also shows the ± px uncertainty.
- Core logic (snapping and edge detection in the ROI) goes in `core/` with no Qt. The UI goes in `ui/`.

## Tests
- Core: on a synthetic scale bar (conftest), the ROI detection finds the ends within ±1 px, including for a box drawn loosely/too wide.
- UI (pytest-qt): the mode toggle persists; rectangle length = width only (a tilted drag gives the same result); the handles resize and move the box and the px readout updates; in level-line mode y stays locked; free-line mode shows the tilt warning above 1°.
